## File Structure Pattern

- Root-level pages (`src/pages/index.astro`, `src/pages/pricing.astro`) are the **English** versions.
- Translated pages live under `src/pages/{lang}/` (e.g. `src/pages/de/index.astro`).
- Each page imports its JSON and passes it as a `translations` prop to components.
- Components do **not** import translation files directly — the page does and passes it down.

---

## Translation Props Pattern

```astro
import translations from '../../content/translations/de.json';
// Pass full object or sub-key:
<Header translations={translations.header} />
<UseCases translations={translations} />
```

For client-side `<script>` blocks, use `define:vars` to inject values (makes the script inline — no imports allowed):

```astro
<script define:vars={{ items: translations.someList }}>
  // items is available as a plain JS variable
</script>
```

### Changelog page — extra localization notes

`/changelog` (root, EN) and `/fr/changelog` merge two data sources: blog posts tagged
`"announcement"` (derived) and a frozen legacy archive in `src/data/legacy-releases.ts`.

- The **derived** rows come from the **English** announcement posts (one row per release,
  whatever languages it was written in). On `/fr/changelog` each row takes the best of
  three sources: a real French translation linked by `translationOf` (French copy, French
  link), else `src/data/changelog-blog-fr.ts` keyed by post slug (French copy, English
  link), else the English title/description. A new locale would add a parallel
  `blogFr`-style map. See the Blog section above.
- The **legacy archive** is bilingual: each entry carries `title`/`summary` (EN) and
  `titleFr`/`summaryFr` (FR). A new locale needs a `{lang}Fr`-style field pair added there,
  plus a `/{lang}/changelog.astro` route (copy `fr/changelog.astro`, swap the JSON import and
  the `FormattedDate` locale) and a `changelog` block in `{lang}.json`.
- `FormattedDate.astro` takes an optional `locale` prop (default `en-us`); the FR route passes
  `locale="fr-FR"` for French month formatting.

### Blog — one collection, many languages

Shipped 2026-08-25. The blog was English-only; French how-to content had nowhere to
live, which is why every FR page linked out to an English post marked "(en anglais)".

**Shape:** one `blog` collection holds every language. Two frontmatter fields drive it:

| Field | Meaning |
|---|---|
| `locale` | `"en"` (default) or `"fr"`. Defaulting means the English corpus needed no edits. |
| `translationOf` | The `id` of the counterpart post in another language. One direction only. |

- **Files:** non-English posts live in `src/content/blog/{locale}/`. The collection glob
  already recurses, so no loader change was needed.
- **URLs:** `/fr/blog/<slug>/`, matching every other localized route. **Slugs are written
  in the target language** (`comment-creer-un-sondage-sur-discord`, not a translated
  English slug) — ranking for `sondage discord` is the entire point.
- **Routes:** `src/pages/fr/blog/index.astro` + `[...slug].astro`, mirroring the English
  pair. Each filters `getStaticPaths` to its own locale.
- **Feeds:** `/rss.xml` is EN-only, `/fr/rss.xml` is FR-only. One feed per language. (The
  English feed also stopped syndicating drafts in the same change; it had been reading
  the collection unfiltered, so it pushed unpublished posts to subscribers while `/blog`
  hid them.)
- **Sitemap:** no config change. Pages are picked up automatically and hreflang stays
  page-level. **Do not enable `@astrojs/sitemap`'s `i18n` option** — it assumes every URL
  exists in every locale, which is false here, and would emit hreflang pointing at 404s.

**⚠️ Every consumer of `getCollection('blog')` must filter by locale**, or French posts
leak into the English listing, the English feed and both changelog pages. Use
**`src/utils/blog.ts`** instead of reading the collection directly:

```ts
import { getBlogPosts, postUrl, postAlternates } from '../utils/blog';

const posts = await getBlogPosts('en');        // locale-filtered, drafts out, newest first
<a href={postUrl(post)}>                        // /blog/x/ or /fr/blog/x/
```

**hreflang is emitted only for a linked pair** (`postAlternates`). A post with no
counterpart gets none, on purpose: hreflang has to be reciprocal, and locale-original
posts (French-first content with no English twin) are the expected common case, not the
exception.

**`BlogPost.astro` is locale-aware**: it picks the translations file from the post's
`locale`, sets `<html lang>`, adds `inLanguage` to the `BlogPosting` schema, passes the
date locale to `FormattedDate`, and reads its four chrome strings from a `blogPost` block
in the locale JSON (`by`, `lastUpdatedOn`, `readMoreTitle`, `faqTitle`). "Read more" is
built from the route's already-locale-filtered list, so it never crosses languages, and
it renders nothing at all when a language has only one post.

**`/fr/changelog` upgrades itself.** Its rows now prefer, in order: a real French
translation (French copy, French link), then `changelog-blog-fr.ts` (French copy, English
link), then the English post. Publishing a French translation improves its changelog row
for free.

**~~Known limitation~~ FIXED 2026-08-25** — `LanguageSwitcher.astro` used to swap the locale
prefix and keep the path, 404-ing on blog posts and on any page missing in the target
locale. See the section below; it now resolves targets against the real route list and
falls back to the locale homepage.

## LanguageSwitcher — real links, not a JS jump

**The localized tree used to have no crawlable inbound links at all.** The switcher was a
`<select>` whose only navigation was `window.location.pathname = …` in a click handler, so
an audit on 2026-08-25 found **0 of 98 English pages linked to any `/fr/` page**. Search
Console agreed: `https://subo.gg/fr/polls/` reported *"Referring page: None detected"* while
sitting in **Crawled - currently not indexed**. A whole language was an island reachable
only by sitemap and hreflang.

It now renders real `<a href>` links resolved at build time. **0 → 86 English pages linking
into `/fr/`.** (The 12 without a switcher are the outbound redirect stubs, which have no
footer and are excluded from the sitemap anyway.)

Three things it does deliberately:

- **Targets are checked, not guessed.** `import.meta.glob('/src/pages/**/*.astro')`
  enumerates real routes at build time, so a locale that lacks the page links to that
  locale's homepage instead of 404-ing. This is what fixed the blog case: slugs differ per
  language by design, so `/fr/blog/<french-slug>` has no same-path English twin.
- **Hrefs carry the trailing slash**, matching the canonical (now the sitewide rule, below).
- **The localStorage preference still gets set** on click, then the anchor navigates on its
  own. That preference is what BaseHead's redirect script reads on `/` and `/pricing`.

Dynamic routes (`[...slug]`, `[redirect]`) are skipped by the glob, which is correct: their
params are not knowable at that point.

## Internal links: always end with a trailing slash

**Every internal link ends with `/`.** `href="/polls/"`, never `href="/polls"`. The
canonical is generated from the URL and always carries one, so a link without it points at
a URL the site does not consider canonical.

This was sitewide until 2026-08-25: **7,893 links across 119 URLs**, English included, and
the homepage had 24 internal links of which **zero** used the canonical form. Search Console
reported *"Referring page: None detected"* for `https://subo.gg/fr/polls/` while 14 pages
linked to `/fr/polls`, which is what the mismatch looks like from Google's side.

Applies to every way a link gets written:

```astro
<a href="/polls/">                          <!-- attribute -->
href={`/templates/${slug}/`}                 <!-- template literal -->
const pricingHref = `/${locale}/pricing/`;   <!-- computed -->
```
```json
{ "text": "Sondages", "href": "/fr/polls/" }
```
```markdown
[the poll how-to](/blog/how-to-create-a-discord-poll-with-or-without-a-bot/)
```

Also `recipeUrl` in template frontmatter. **Exception:** anchors keep the slash before the
fragment (`/recipes/#engage`), and non-page assets never take one (`/rss.xml`,
`/llms.txt`, images).

Not currently guarded. The audit is a few lines if it regresses: compare every `href="/…"`
in `dist/` against the set of built `index.html` paths.

## hreflang — the rules, and the guard that enforces them

**hreflang hrefs must exactly match the canonical of the page they point at, trailing
slash included.** Canonicals are generated from the URL and always carry a slash;
`alternates` arrays are hand-written per page and are where the slash gets dropped.

This is not hypothetical. On **2026-08-23** Search Console reported *"Duplicate, Google
chose different canonical than user"* for `https://subo.gg/pricing/`: the page declared
`/pricing/` canonical while its own cluster named `/pricing`. **42 of 52 hreflang-bearing
pages had it, 214 hrefs**, fixed 2026-08-25. The 10 that were clean were the blog posts,
which build hrefs from `postUrl()` instead of hand-writing them.

**`npm run check:hreflang`** (in `npm run check`, after the build) enforces four rules
against `dist/`, because the rendered HTML is what Google reads:

| # | Rule | Why |
|---|---|---|
| 1 | Canonical appears in the page's own cluster | The `/pricing` bug. Names the trailing-slash case explicitly. |
| 2 | Reciprocity: if A lists B, B lists A | hreflang is ignored unless bidirectional. `x-default` exempt, it is a fallback pointer not a language claim. |
| 3 | Every href is a page in this build | Catches typos and removed routes. |
| 4 | No duplicate hreflang code per page | |

`x-default` missing from a multi-language cluster is a **note**, not a failure (Google
recommends but does not require it). Verified by inducing each failure in both directions.

**What it cannot check:** that the language code matches the language of the page. A French
page annotated `hreflang="de"` passes everything. That one is still on you.

**When adding a localized route**, the reciprocity rule means you must add the new locale to
**every existing page in that cluster**, not just create the new page. The guard will tell
you exactly which pages you missed.

## BaseHead.astro — Language Redirect Logic

`src/components/BaseHead.astro` contains a client-side script that auto-redirects users to their preferred language on `/` and `/pricing`.

**Important pitfall:** The redirect block that covers both `/` and `/pricing` must preserve the path suffix. Use `suffix` to avoid stripping `/pricing`:

```js
if (['/', '/pricing'].includes(path)) {
  var suffix = path === '/pricing' ? '/pricing' : '';
  if (preferredLang && ['fr','es','de'].includes(preferredLang)) {
    window.location.pathname = '/' + preferredLang + suffix;
    return;
  }
  if (!preferredLang) {
    var userLang = (navigator.language || navigator.userLanguage || 'en').slice(0,2);
    if (!['en','fr','es','de'].includes(userLang)) userLang = 'en';
    if (['fr','es','de'].includes(userLang)) {
      window.location.pathname = '/' + userLang + suffix;
    }
  }
}
```

Without the `suffix`, clicking "Pricing" on a localized page would redirect to the homepage instead.
